Methodology & Performance

How the conviction score is built, how the index is constructed and rebalanced, and how to read the track record. Every figure on this page is derived from the same code that runs the terminal — no estimates unless explicitly flagged.

1 · The Conviction Score (0–100)

Each asset in the universe (CoinGecko top-250 by market cap, non-stable) receives a single conviction score. It is the sum of four modules. The exact same function runs in two places — the live terminal (JavaScript) and the nightly index builder (Python) — and they are tested to produce identical numbers. This is deliberate: a single source of truth prevents the "live leaders" and the "index holdings" from silently diverging.

A Liquidity Fit  ·  weight 0–30

Measures turnover (24h volume ÷ market cap). Capital needs a liquid venue; too little is unexitable, too much signals wash trading.

turnover = volume / market_cap  (fraction)
a = 10 + (turnover/0.30)·20  for turnover ≤ 0.30
a = 30 − |turnover − 0.45|/0.15·6  for ≤ 0.60
a = 20 − (turnover − 0.60)/0.60·12  for ≤ 1.20
a = max(2, 8 − (turnover − 1.20)·4)  above

Peaks in the 30–60% turnover band; sharp penalty below 10% (illiquid) and above 75% (wash risk).

B Stability / ERA  ·  weight 0–20

A proxy for emission-vs-adoption health from 24h price stability. Calm assets score higher; violent moves score lower.

ag = 15 if |chg|<5%  else  10 if |chg|<15%  else  5
era = 5 / ag
b = 20 if era<0.7  else  15 if era<1.0  else  10 if era<1.5  else  5 if era<2.0  else  0

When a Dune unlock/vesting query is connected (repository secret DUNE_UNLOCK_QUERY_ID), Module B is replaced by real on-chain ERA — emission schedule vs network adoption — instead of this 24h-stability proxy. Until then it is shown as a proxy, never fabricated.

C Depth + Momentum  ·  weight 0–40

Market-cap depth (log-scaled, rewards real size without over-weighting mega-caps) plus a 24h momentum curve that rewards measured strength and punishes both crashes and vertical overextension.

depth = clamp((log10(mc) − 6) / 4, 0, 1)
cd = depth · 20
cm = 4 if chg<−15%  …  14+chg if chg≤8%  …  20 if chg≤20%  …  decays above
c = cd + cm

D LAVL Leverage Overlay  ·  multiplies momentum

The Liquidity-Adjusted Velocity & Leverage regime applies a RiskMultperp to the momentum component, sourced from live perpetual-futures funding (Bybit primary, OKX fallback — keyless, geo-resilient). It penalizes overheated longs (funding > 0.05% → ×0.85) and rewards short capitulation (negative funding → ×1.15). Assets with no perp market, or when the feed is unavailable, default to neutral ×1.0.

c = cd + (cm · RiskMult_perp)
RiskMult_perp ∈ {0.85, 1.0, 1.15}

This is the only module the live terminal cannot compute in-browser (no cross-origin perp feed). The terminal instead reads each asset's perp_mult from the nightly ledger, so the live leaders and the index use the same overlay.

conviction = clamp( a + b + c , 0, 100 )   signal: STRONG ≥80 · BUY ≥70 · HOLD ≥55 · WATCH ≥40 · AVOID <40
Conjunctive gate. Beyond the score, an asset is "qualified" only if it simultaneously passes Liquidity (turnover 30–60%), Dilution (FDV/MC ≤ 2.0), and Regime (not COMPRESS / LIQ TRAP). The gate is a hard filter on eligibility; the score is the ranking among eligible assets. The Alpha Map shows both.

2 · The Conviction-Weighted Index

The index is a paper portfolio of the top-10 eligible assets by conviction, held with score-proportional weights — each asset's weight is its conviction ÷ the sum of the top-10 convictions. This is a conviction tilt, not an equal-weight bucket: higher-conviction assets command larger allocations.

Construction

holdings = top 10 by conviction (eligible universe)
w_i = conviction_i / Σ conviction_j  (j = 1..10)
Σ w_i = 1.0

Entry prices are snapped at rebalance. Between rebalances, each holding's weight drifts with its live price — the dashboard shows both the target weight (at rebalance) and the live weight (current), plus the per-asset return and the cumulative basket vs benchmark.

Rebalance cadence

The basket rebalances on two triggers, whichever comes first:

TriggerConditionWhy
CalendarEvery 7 daysWeekly refresh prevents multi-week compounding drift from polluting the macro comparison; the global-cap baseline is re-locked at each rebalance.
Drift / membershipA holding drops out of the top-10 eligible setIf conviction re-ranking ejects a name, the basket realigns immediately rather than carrying a fallen asset for a week.
The benchmark baseline is locked at each rebalance event, not at basket creation. This is the key architectural fix: every rebalance period starts from a clean baseline, so the basket-vs-market comparison is horizon-matched and not distorted by stale entry marks.

Benchmark — the #2 Global Market Cap

The index is measured against total crypto market cap (CoinGecko /global), entry-anchored at the last rebalance. This is an apples-to-apples macro comparison: the same asset class, the same window. Reported as basket_return vs benchmark_return, with alpha = basket − benchmark.

3 · Performance & Track Record

The nightly job (06:17 UTC) appends one row per day to ledger/index.csv and recomputes the cumulative basket and benchmark curves in ledger/index.json. The terminal's "Conviction-Weighted Index" panel renders this as a live paper track record.

What the audit trail shows

  • Per-asset entry vs current price, target weight vs live (drifted) weight, and per-asset return — a full audit of every position, every day.
  • Rebalance flag — which days reset the baseline (so you can see exactly when the horizon-matched window starts).
  • Global market cap at each snapshot, so the benchmark is fully reconstructable from the ledger alone.
Risk statistics are computed from the ledger, not invented. Once ≥30 days of history exist, Sharpe (on the daily basket-return series vs the benchmark's), maximum drawdown of the cumulative basket curve, and rebalance win-rate (fraction of rebalances where the dropped asset underperformed the added one) are derived directly from ledger/index.csv — no extra API calls, no fabricated history. They appear here once the nightly has accrued enough rows.

3.5 · Rebalance Discipline & Risk Overlays

Four guards keep the paper track record honest and the turnover under control. All are derived from the ledger — none require extra feeds.

A Rebalance Hysteresis (Turnover Drag Buffer)

A holding is ejected only if it drops to rank ≥ 13 or its conviction falls more than 5 points below the marginal entrant (rank 11). A #10↔#11 flip therefore does not trigger a rebalance — it would only churn alpha in execution costs. The basket still rebalances weekly on the calendar, or immediately when a name structurally falls out of the top tier.

B Execution-Adjusted Counterfactual

Real fills cost spread + fees. The raw paper return is kept pure; in parallel we track an execution-adjusted return that deducts a one-way 25 bps cost applied to the one-way turnover at each rebalance. Turnover = Σ|new weight − old weight| across changed holdings. Genesis (basket creation) charges no cost. Both curves ship in ledger/index.json so you see the frictionless vs real-world path side by side.

exec_adjusted_return = raw_return − (25bps) × (one_way_turnover)

C Ejection Alpha Delta

At each rebalance we record the ejected vs entrant symbols and the ejected holdings' average realized return since entry. Δeject = Rentrant(0 at entry) − Rejected(realized). A positive cumulative Δ means the rotation dropped underperformers. The full Rentrant-vs-Rejected both-over-the-holding-window figure is refined automatically once ≥2 rebalances exist (entry prices are persisted in basket.json).

Δ_eject = mean(R_entrant) − mean(R_ejected);  cumulative Δ tracked in index.json

D Macro Liquidity Gate — Passive / Display-Only

The 7-day total market-cap trend is computed from the ledger: RISK-OFF if global cap is down > 8% over 7 days, else RISK-ON. This is shown as a passive regime pill in the Index panel and recorded in ledger/index.csv — it provides macro context but does not alter holdings. Promoting it to an active filter (e.g. raise the gate threshold in risk-off) is deferred until enough history exists to backtest whether it adds alpha.

Sharpe convention (pinned). When ≥30 days accrue: Sharpe = mean(daily basket return) / std(daily basket return) × √365, with risk-free rate = 0. Max drawdown = largest peak-to-trough decline of the cumulative basket curve. Both are recomputed nightly from ledger/index.csv and surfaced in ledger/index.json under risk.

4 · Honest Caveats

  • Live vs snapshot. The Alpha Map's "top-10 conviction leaders" are computed live from CoinGecko at page load. The Index holdings come from the 06:17 UTC nightly snapshot. Intraday price moves mean the two lists can differ slightly by ordering — this is expected, not a bug. The Index is the authoritative, persisted record.
  • Module B is a proxy until Dune is connected. Without DUNE_UNLOCK_QUERY_ID, ERA uses 24h stability. Real on-chain unlock schedules replace it when configured. We never estimate unlock data we don't have.
  • Perp overlay via server-side feed. RiskMultperp requires a derivatives feed (Bybit/OKX) that can't be called cross-origin from the browser. The terminal reads the nightly-computed perp_mult so it stays consistent with the index.
  • Free-tier data limits. No intraday, RSI, order-book, or funding history from the free CoinGecko tier. We scope every module to real payload fields and label anything we cannot source as unavailable.
  • Paper only. This is a research signal system, not investment advice. Conviction is a quantitative tilt, not a promise.
